## 1. 목적

Python 프로토타입을 **운영 환경에서 안정적으로 동작하는 양산 클라이언트**로 대체한다. 본 Phase가 완료되면:

- 단일 .exe 인스톨러로 어느 매장 PC에든 5분 안에 설치할 수 있다.
- .NET 런타임 없이 self-contained로 동작한다.
- 새 버전 출시 시 매장 PC에 자동 업데이트가 적용된다.
- ESC/POS 출력 안정성·메모리·CPU·시작 시간이 Python 대비 개선되어 있다.

> ⚠️ Phase 3의 Python 클라이언트와 **본 빌드는 프로토콜 호환성을 유지**해야 한다. 동일 Server C가 둘 다 받아야 점진적 전환이 가능하다.

## 3. 세부 작업 항목

### 3.1 프로젝트 초기화

PRD §10.2.

- [ ] .NET 8 SDK, WinForms 프로젝트 (`dotnet new winforms`)

- [ ] csproj: `<PublishSingleFile>true</PublishSingleFile>`, `<SelfContained>true</SelfContained>`, `<RuntimeIdentifier>win-x64</RuntimeIdentifier>`
- [ ] 단일 인스턴스 보장 (Mutex)

### 3.2 WebSocket 클라이언트

PRD §7.

- [ ] `ClientWebSocket` 사용 (내장)
- [ ] 메시지 수신 루프 + 송신 큐 (concurrent)
- [ ] 끊김 시 지수 백오프 (1s → 30s → 5min)
- [ ] ping/pong 30초 (CloseStatus 추적)
- [ ] 인증 첫 메시지 + `last_known_job_id` (로컬에서 영속)

### 3.3 출력 어댑터

PRD §4.3.

- [ ] **1순위**: Windows Print Spooler raw 모드 — winspool.drv P/Invoke
  - `OpenPrinter`, `StartDocPrinter`(RAW datatype), `StartPagePrinter`, `WritePrinter`, `EndPagePrinter`, `EndDocPrinter`, `ClosePrinter`
- [ ] **폴백**: ESCPOS_NET의 `FilePrinter`/`NetworkPrinter`/`SerialPrinter` (USB 직접 접근은 매장 드라이버를 깨므로 사용하지 않음)
- [ ] 프린터 이름은 설정에서 capability별로 매핑
- [ ] 프린터 상태 확인 (GetPrinter API, JOB_STATUS_*)

- [ ] 80mm/58mm 폭별 컬럼 계산
- [ ] 출력 종류별 헤더 차별화 (주방/카운터/바)

## 4. 작업 순서

1. 프로젝트 초기화 + WS 연결 (D1, D2)
2. 인증 + 재접속 (D3) → Server C와 핸드셰이크 확인
3. Print Spooler raw 출력 (D4) → 콘솔 앱으로 가짜 페이로드 출력 시험
4. 페이로드 빌더 + 한글 인코딩 (D5, D6)
5. ACK + 중복 방지 (D10)
6. 트레이 UI + 로그 (D7, D8)
7. 영속화 (D9)
8. Velopack 통합 + 채널 셋업 (D11, D13)
9. 빌드 스크립트 + 단일 .exe (D12)
10. 베타 매장 전환 → 본 빌드로 교체
