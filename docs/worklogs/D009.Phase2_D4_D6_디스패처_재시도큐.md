## 3. 핵심 결정

### 3.1 백오프 정책 (1-based attempt)
| attempt N 후 timeout | 동작 |
|---|---|
| 1 → | 1초 backoff 후 재시도 (attempt 2) |
| 2 → | 3초 backoff 후 재시도 (attempt 3) |
| 3 → | 더 이상 재시도 없음 → `markFailed` + PHP 콜백 |

`BACKOFF_MS[3] = 10초` 도 보존하지만 실제로는 attempt 3 후 즉시 failed (`attempt_count >= MAX_ATTEMPTS`). 향후 정책 완화 시 활용.

### 3.2 in-flight set 으로 중복 방지
- `dispatcher.inFlight: Set<number>` — dispatch 직후 add, ACK 수신 / 10초 timeout 시 remove
- 동일 job 의 짧은 시간 내 재dispatch 방지 (PRD §8.4)
- 재시도 워커가 1초 주기로 도는데, attempt N 의 ACK 타임아웃 (10초) 이 끝나기 전엔 in-flight 가 보호

### 3.3 attempt race condition 방어
`notifyAckTimeout(jobId, dispatchedAttempt)` 는 호출 시점에 SQLite 의 `attempt_count` 와 dispatch 시 캡처한 값을 비교. 다르면 무동작.
- 시나리오: dispatch (attempt 1) → 10초 후 timeout 발화 시점에 이미 ACK 'printed' 수신해서 status='printed' 인 경우
  → `job.status !== 'sent'` 에서 걸러짐
- 시나리오: 같은 job 이 webhook 으로 다시 들어와서 또 dispatch 된 경우
  → `attempt_count !== dispatchedAttempt` 에서 걸러짐

### 3.4 PHP 콜백 = D009 stub
- `php/callback.ts` 의 `notifyPhpJobPrinted` / `notifyPhpJobFailed` 는 로깅만
- 본격 POST 는 D010 — 인터페이스만 합의해서 retry.ts / ack.ts 가 호출
- D010 에서 본 함수 본체만 채워 fetch + HMAC + 자체 재시도 1s/5s/30s 구현

### 3.5 sync.ts 단순화
- D008 의 sync.ts 는 별도 SQLite SELECT + sendJson 으로 자체 dispatch 했음
- D009 에서 dispatcher 가 도입되며 sync 는 `tryDispatchShop(jobs, {lastKnownJobId, capabilities})` 로 단축
- 결과: 같은 매장에 더 최근 접속한 다른 client 가 있으면 dispatcher 가 그쪽을 우선할 수 있음 — 의도된 동작

## 5. 주의사항

### 5.1 scheduleRetry 의 시간 형식
- D009 에서 ISO8601 (`new Date().toISOString()`) 저장
- SQLite `datetime()` 함수는 둘 다 받지만 SQL 형식 ('YYYY-MM-DD HH:MM:SS') 으로 통일하는 것도 고려 — 후속 단위에서 검토
- 본 단위에서는 `datetime(next_retry_at) <= datetime('now')` 로 wrapping 하여 안전

### 5.2 mock PHP 서버
- `scripts/dev_php_mock.mjs` 는 운영 배포에 절대 포함되지 않음 (PM2 ecosystem 에 등록 안 함)
- 검증 시: `cp .env .env.backup && sed -i 's|PHP_API_BASE=.*|PHP_API_BASE=http://127.0.0.1:18080|' .env` 후 실행
- 검증 후 반드시 `.env` 원복 — 본 단위에서는 자동 원복함

### 5.3 D010 에서 채울 것
- `php/callback.ts` 의 두 함수 본체:
  - `POST {PHP_API_BASE}/api/print_jobs_status.php?id={jobId}` (PHP 측이 ?id= 쿼리스트링으로 받음)
  - HMAC `X-Signature` 헤더 (PRINT_SHARED_SECRET, SHA256)
  - body: `{status, printed_at?, client_idx, last_error?}`
  - 5초 타임아웃, 실패 시 1s/5s/30s 자체 재시도
- D009 에서 호출 시점은 이미 fix:
  - `markPrinted` 직후 → `notifyPhpJobPrinted({jobId, printedAtIso, clientIdx})`
  - `markFailed` 직후 (client ACK 'failed') → `notifyPhpJobFailed(jobId, errText, clientIdx)`
  - `markFailed` 직후 (3회 timeout) → `notifyPhpJobFailed(jobId, '3 attempts exhausted (ACK timeout)')`
