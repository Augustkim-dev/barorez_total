## 3. 운영 적용 절차 (사용자 수동)

본 단위에서 코드/문서 작성은 완료. 실제 운영 적용 시 다음 순서로 진행:

### 3.1 운영 서버 환경 준비
- [ ] Node.js 20 LTS 설치 (`node -v` ≥ 20)
- [ ] Apache 모듈 활성화: `sudo a2enmod proxy proxy_http proxy_wstunnel` (또는 RHEL 의 LoadModule)
- [ ] 가용성 확인: `apachectl -M | grep -E "proxy_wstunnel|proxy_http"`
- [ ] PM2 글로벌 설치: `sudo npm install -g pm2`

### 3.2 코드 배포
- [ ] git pull 또는 rsync 로 `server_c/` 동기화
- [ ] `cd server_c && npm install --omit=dev`
- [ ] `npm run build` (tsc → dist/)

### 3.3 .env 설정 (운영 시크릿 동기화)
- [ ] `.env.example` → `.env` 복사
- [ ] `PRINT_SHARED_SECRET` 값을 PHP `cfg/config.inc.php` 의 동명 상수와 **반드시 동일하게**
- [ ] `PHP_API_BASE=https://barorez.com`
- [ ] `NODE_ENV=production` (pino-roll 파일 로그 활성화 trigger)
- [ ] `LOG_LEVEL=info`

### 3.4 PM2 기동
- [ ] `pm2 start ecosystem.config.cjs`
- [ ] `pm2 save`
- [ ] `sudo pm2 startup`  ← 출력된 명령 그대로 실행
- [ ] 서버 reboot 후 `pm2 list` 에서 `barorez-server-c` 가 online 상태 확인

### 3.5 Apache 적용
- [ ] `Include /var/www/.../server_c/deploy/apache_printsvc.conf` 를 barorez.com vhost 의 `<VirtualHost *:443>` 안에 추가
- [ ] `sudo apachectl configtest`
- [ ] `sudo systemctl reload apache2`

### 3.6 통합 검증
- [ ] `curl -sS https://barorez.com/printsvc/health` → `{ok:true,...}` 응답
- [ ] `wscat -c wss://barorez.com/printsvc/ws` → 5초 후 close 4001 'auth timeout' 정상
- [ ] PHP `cfg/config.inc.php` 에 `PRINT_CLIENT_TOKEN_SALT` 값 채움 (개발 머신은 빈 값, 운영은 필수)
- [ ] `POST https://barorez.com/api/print_clients_register.php` (admin 세션) → mock 매장 PC 1개 등록, plain_token 받음
- [ ] 실제 매장 PC (또는 검증용 스크립트) 가 wss://barorez.com/printsvc/ws 접속 + auth → auth_ok 확인
- [ ] 활성 매장(sh_idx=48) 에서 주문 발생 → Server C 로그에서 `webhook_received` + `job_dispatched` 확인
- [ ] client 가 ACK 'printed' → PHP `print_job_t.status='printed'` 확인 (DB 직접 조회)

### 3.7 PM2 영속성 검증
- [ ] `pm2 stop barorez-server-c && pm2 start barorez-server-c` 후 `data/server_c.db` 의 미완료 job 정상 복구
- [ ] `pm2 kill` 후 `sudo systemctl restart apache2` 와 함께 서버 reboot 시뮬레이션 — 부팅 후 자동 기동 확인

### 3.8 HMAC 시크릿 회전 (Phase 2 종료 시 의무)
Phase 1 D004 에서 채팅창에 노출된 시크릿이 운영 서버에서 그대로 사용 중. Phase 2 적용 시점에 동시 회전:

- [ ] Server C `.env` 의 `PRINT_SHARED_SECRET` 동일 값으로 갱신
- [ ] `sudo systemctl reload apache2` + `pm2 restart barorez-server-c` 동시 (수십 초 webhook 손실 가능 — 트래픽 적은 시간 권장)
- [ ] 회전 직후 활성 매장 1건 주문 → 정상 흐름 확인

## 5. Phase 3 인계 사항

Phase 3 (Python 프로토타입 + 1매장 베타) 시작 시 필요한 것:

### 5.1 Phase 3 가 의존하는 Phase 2 산출물
- WS endpoint: `wss://barorez.com/printsvc/ws`
- 인증 프로토콜: `protocol.ts` 의 `AuthMessageSchema` (`type:'auth', client_id, token, capabilities[], app_version, last_known_job_id?`)
- ACK 프로토콜: `AckMessageSchema` (`type:'ack', job_id, status:'printed'|'failed', printed_at?, error_code?, error_message?`)
- ping/pong: 30초 주기, 2회 누락 시 close 4006
- 토큰 발급: `POST https://barorez.com/api/print_clients_register.php` (admin 세션)

### 5.2 Phase 3 가 검증해야 할 것
- Python 클라이언트 (PyWebSocket / websockets 라이브러리) 의 인증 + 재접속 + ACK 흐름
- 실제 영수증 프린터 (보통 ESC/POS) 연동
- 1매장 베타 운영 — 매장 PC 1대 등록, 실주문 1건 출력
- (Phase 1) `print_route_rule_t` 의 카테고리→프린터 매핑 운영 검증

### 5.3 알려진 미해결 항목 (Phase 2 범위 외)
- Admin UI: PC 등록/토큰 발급 UI, 라우팅 규칙 편집 UI — Phase 4
- C# 본 빌드 (Velopack 자동 업데이트) — Phase 5
- Prometheus / Slack 알림 / 운영 dashboard — Phase 6
- 같은 capability client 다수 시 우선순위의 정교한 정책 (현재는 last_connected 최근) — Phase 6 운영 데이터 보고 결정
