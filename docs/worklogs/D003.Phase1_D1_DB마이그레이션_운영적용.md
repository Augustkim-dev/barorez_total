### 1.2 실제 적용

- **방식**: 사용자가 phpMyAdmin / SSH 터미널로 직접 실행
- **백업**: 적용 직전 mysqldump 1회 별도 수행
- **결과**: 정상 완료 (사용자 회신 "정상 완료")

### 1.3 생성된 스키마 객체

| 테이블 | 컬럼 수 | 인덱스 | 엔진 |
|---|---|---|---|
| `print_client_t` | 10 | PRIMARY(client_idx), idx_shop_active(shop_idx, is_active) | InnoDB/utf8mb4 |
| `print_route_rule_t` | 6 | PRIMARY(rule_idx), idx_shop_category(shop_idx, category_idx) | InnoDB/utf8mb4 |
| `print_job_t` | 13 | PRIMARY(job_idx), idx_shop_status_created(shop_idx, status, created_at) | InnoDB/utf8mb4 |

**FK 제약**: 없음 (사전 결정 [D002](D002.DB변경영향도_정량평가_FK정책결정.md)에 따라). 컬럼은 단순 `INT NOT NULL`로 정의되었으며 정합성은 PHP 코드에서 보장.

## 2. 코드 변경

### 2.1 `cfg/table.inc.php`

기존 등록 컨벤션(`$CFG_TBL['카테고리']['타입'] = '테이블명_t'`)에 맞춰 신규 그룹 `print` 추가:

```php
// 영수증 자동 출력
$CFG_TBL['print']['client']        = 'print_client_t';
$CFG_TBL['print']['route_rule']    = 'print_route_rule_t';
$CFG_TBL['print']['job']           = 'print_job_t';
```

기존 등록 항목은 전혀 건드리지 않음 — 본 파일을 include하는 모든 코드 영향 없음.

## 4. 검증 결과

사용자가 직접 phpMyAdmin/SSH로 실행 후 "정상 완료" 회신.

권장 추가 검증 (사용자가 시간이 될 때 확인 가능):
- 메인 페이지 1건, 주문 흐름 1건 smoke test → 기존 서비스 영향 없음 확인
- `SELECT COUNT(*) FROM print_client_t;` 등 3개 신규 테이블 빈 SELECT (0 반환 기대)
