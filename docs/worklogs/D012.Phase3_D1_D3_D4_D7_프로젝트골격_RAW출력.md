## 1. 한 줄 요약
`client_python/` 신규 패키지. 가짜 페이로드 JSON → ESC/POS 바이트 → Print Spooler RAW 출력 경로를 WS 통신과 분리해 **단독 검증**. 한글 CP949 인코딩과 오류 4종(`PRINTER_OFFLINE` / `PRINTER_OUT_OF_PAPER` / `UNSUPPORTED_ENCODING` / `UNKNOWN`) 분기까지 본 단위에서 닫음.

## 3. 검증

### 3.1 dump 모드 자체 검증 (실 프린터 없이)
저장소 루트에서 실행:

```powershell
python -m client_python.tools.print_sample `
  client_python/sample_payloads/kitchen_basic.json --dump kitchen_basic.bin
# wrote 436 bytes -> kitchen_basic.bin
```

생성된 `.bin` 의 골격 검증:
- 시작 바이트: `1b 40` (ESC @ INIT) — 확인됨
- 종료 바이트: `1d 56 42 00` (GS V 66 0, partial cut) — 확인됨
- 본문을 CP949 로 decode → "주방", "테이블", "김치찌개", "포크" 모두 추출 가능 — 확인됨

`kitchen_long` (778B), `counter_basic` (298B) 동일하게 통과.

### 3.2 UNSUPPORTED_ENCODING 분기 검증
`unsupported_chars.json` 실행 시 exit code = 3 + stderr:
```
format failed [UNSUPPORTED_ENCODING]: cannot encode text in cp949: ...
```
→ PRD §8.6 오류 분류 그대로 동작. ACK 시 `error_code='UNSUPPORTED_ENCODING'` 으로 송신될 것 (D013 에서 결합).

### 3.3 실 프린터 출력 (사용자 액션 필요)
다음 절차로 사용자가 실 프린터 검증 예정:

```powershell
cp client_python/config.example.ini client_python/config.ini
# config.ini 의 printer.name 을 Windows '장치 및 프린터' 의 실제 이름으로 변경
# (확인용: python -m client_python.tools.list_printers)
python -m client_python.tools.print_sample client_python/sample_payloads/kitchen_basic.json
```

성공 기준:
- 영수증 한 장 인쇄 (헤더 "주방" 큰 글자 + 테이블 + 메뉴 3 + 메모 + 푸터 + cut)
- 한글 정상 출력 (깨짐 0)
- 컬럼 정렬 어긋남 0 (폭 48 기준 우측 수량 정렬)

## 5. 결정 사항 — D013 진입 전 확정 필요

- **실 프린터 모델명 최종 확정**: 사용자가 "국내 주력 모델 (Sewoo SLK / SAM4S / BIXOLON)" 로 답변, 세부 모델명 미입력. config.ini 의 `name` 항목으로 사용자가 직접 입력하는 방식이라 코드 변경 없음. 다만 D013 검증 시점에 실 프린터 1대 모델명/펌웨어 한글 코드페이지를 확인하여 본 worklog 부록에 기재.
- **escpos_codepage_id** 빈 값으로 두고 출력해보고, 한글 깨짐 시 13/22 시도.
- **베타 client 토큰 발급 방식** (수동 SQL vs 임시 CLI) — D013 의 첫 결정.
