## 3. 사전 점검으로 결정된 컨벤션

| 항목 | 결정 |
|---|---|
| HTTP 메서드 | **POST** (PRD §7.5 PATCH → 본 프로젝트는 POST 일색이라 변경) |
| 응답 형식 | `header('Content-Type: application/json; charset=utf-8')` + `json_encode([...], JSON_UNESCAPED_UNICODE)` |
| 상태 코드 | `http_response_code()` |
| 시크릿 저장 | `cfg/config.inc.php`에 `define()` 평문 (PortOne/Kakao 등 기존 컨벤션 동일) |

| 테이블명 | 평문 `'print_job_t'` (기존 코드 컨벤션 따름. `$CFG_TBL` 사용은 본 프로젝트 일반 패턴이 아님) |

## 4. 검증 결과

운영 서버에서 사용자가 직접 `test.sh` (test2.sh) 실행:

```
[Step 1] SECRET LEN=64  PFX=37f0...20fe
[검증1] HMAC 누락        → 401  (기대: 401)  ✅
[검증2] 잘못된 HMAC      → 401  (기대: 401)  ✅
[검증3] 정상 HMAC        → {"ok":true,"job_idx":4}  ✅
[검증4] GET 메서드       → 405  (기대: 405)  ✅
```

**결론**: API 동작 정상.

권장 추가 확인 (시간 될 때):
- `SELECT * FROM print_job_t WHERE job_idx=4;` → `status='printed'`, `printed_at='2026-05-12 14:23:02'`, `assigned_client_idx=1` 확인
- 메인 페이지 1건 smoke test (cfg/config.inc.php 수정 영향 점검)
- 검증 정리: `DELETE FROM print_job_t WHERE job_idx=4;`

## 5. 검증 과정에서 학습한 것

### 5.1 lib.inc.php는 CLI에서 출력 오염

초기 스크립트에서 `SECRET=$(php -r "include 'cfg/lib.inc.php'; echo PRINT_SHARED_SECRET;")`로 시크릿을 로드했으나, `lib.inc.php`(320KB, ob_gzhandler 시작·세션 초기화 등)가 CLI 환경에서 stdout에 다른 출력을 흘리면서 `$SECRET` 길이가 64가 아닌 237자가 됨.

해결: `cfg/config.inc.php`만 직접 require:

```bash
SECRET=$(php -d display_errors=0 -r "require 'cfg/config.inc.php'; echo PRINT_SHARED_SECRET;" 2>/dev/null)
```

**향후 시사점**: D3(Webhook 발송 헬퍼)이나 D5(재출력 API) 같은 CLI 환경에서 cfg 상수를 읽어야 할 경우 동일 패턴 사용.

### 5.2 PATCH → POST 변경

PRD §7.5는 PATCH를 명시했으나 본 프로젝트 API는 POST 일색. `.htaccess`에 PATCH 메서드 허용 설정도 없음. POST로 통일하여 컨벤션 일치 + Apache 설정 변경 없이 동작. 의미상 동등하므로 향후 PRD 갱신 시 본문 수정 예정.
