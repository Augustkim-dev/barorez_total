## 1. 한 줄 요약
모든 의존성을 묶은 **단일 .exe** 빌드 자산(`.spec` + `build.bat`) 작성. 점주가 7단계로 자체 설치할 수 있는 한글 가이드(`docs/operations/베타_설치가이드.md`) 1장 정비. `--noconsole` 환경의 `sys.stdout=None` 가드, frozen 모드 자동 시작 분기 보강. 빌드 자체와 모의 검증(.exe 기반 D013 시나리오 재통과)은 사용자가 venv 에서 수행 — **D016 진입 게이트**.

## 2. 신규 산출물

| 파일 | 역할 |
|---|---|
| `client_python/barorez-printer.spec` | PyInstaller spec — `--onefile --noconsole`, UPX 비활성, hidden imports 명시(pystray._win32, PIL.*, win32print, pywintypes, websockets.legacy.client / asyncio.client), tkinter/unittest/pydoc 제외로 크기 절감 |
| `client_python/build.bat` | Windows 빌드 헬퍼 — pyinstaller 미설치 시 자동 설치, 이전 산출물 정리, `python -m PyInstaller barorez-printer.spec --clean --noconfirm`, 산출물 크기 표시 |
| `docs/operations/베타_설치가이드.md` | 점주용 가이드 — 사전 준비물 → 드라이버 설치 → 폴더 구성 → config.ini 확인 → 첫 실행(SmartScreen 안내) → 자동 시작 등록(reg add 1줄) → 작동 확인 → FAQ → 본부 연락처 |

## 3. 확장

| 파일 | 변경 |
|---|---|
| `client_python/src/logger.py` | `sys.stdout is None` 가드 — PyInstaller `--noconsole` 빌드에서 stdout 이 None 인 경우 StreamHandler 등록 건너뜀. TimedRotatingFileHandler 는 정상 동작 |
| `client_python/tools/install_autostart.py` | `_is_frozen()` 추가, `_build_command()` 가 frozen 모드 자동 감지 시 `"<exe path>" --config "<path>"` 형태로 단순 등록. 개발 모드는 기존 pythonw + sys.path 보강 명령 유지 |
| `client_python/README.md` | 단위 진행 표 + D015 빌드 절차 안내 |
| `client_python/.gitignore` | `build_entry.py` (spec 가 생성하는 stub) + `logs/` 추가 |

## 4. 검증

### 4.1 단위 (개발 PC)
- `install_autostart._build_command()` frozen 분기 — `_is_frozen` 패치 + `sys.executable` 패치 시 `"C:\\barorez-printer\\barorez-printer.exe"` 단일 토큰. `--config` 인자 결합 시 `--config <path>` 부속.
- `install_autostart._build_command()` 개발 분기 — `pythonw.exe -c "import sys; sys.path.insert(0, ...); from client_python.tools.run_client import main; sys.exit(main())"` 형태 유지.
- `logger.setup()` 에 `sys.stdout=None` 시뮬레이션 → handlers 에 StreamHandler 없음, TimedRotatingFileHandler 만 등록.

### 4.2 .exe 모의 검증 (사용자 액션, **D016 진입 게이트**)
사용자가 활성 venv 에서 다음 절차 수행:

```powershell
cd client_python
.\build.bat
# 결과: client_python\dist\barorez-printer.exe (예상 ~25~35 MB)
```

이어서 같은 머신에서 .exe 기반 검증:

```powershell
# 기존 venv 가 아닌 .exe 단독 실행
.\dist\barorez-printer.exe
# 트레이 아이콘 표시 확인 + auth_ok 로그 (logs\current.log)
```

검증 시나리오 (D013 재통과 확인):
1. .exe 실행 → 트레이 아이콘 표시 + 로그 `auth sent ... last_known_job_id=<n>`.
2. 운영 매장(shop_id=48)에서 주문 1건 발생 → 영수증 출력 + 트레이 "최근 출력" 메뉴 1줄 추가.
3. Wi-Fi 강제 단절 60초 → 트레이 아이콘 노랑 → 복구 시 단절 동안 발생한 job 일괄 출력 + 초록 복귀.
4. .exe 종료 후 재실행 → auth 메시지에 `last_known_job_id` 포함 (Server C 측 로그로 확인).
5. (가능하면) **별도 깨끗한 PC** 에 `dist\barorez-printer.exe` + `config.ini` 만 복사 후 실행 → Python/venv 없이도 동일 동작.

위 시나리오 통과 시 D016 베타 매장 배포 진입.

## 5. 결정 사항 — D016 진입 전

- **베타 매장 선정 확정** — shop_idx=48 를 그대로 사용할지, 별도 테스트 매장을 정할지. 운영 매장이면 영업 시간/장애 대응 채널 확보 후 진입.
- **장애 대응 채널** — 전화/카톡/원격제어 도구(예: AnyDesk) 중 합의. 가이드 §9 의 빈 칸 채울 정보.
- **운영 기간 정의** — "1주 영업일" 의 기준 (예: 2026-05-19 월요일 ~ 05-25 일요일). 중간 점검 주기 (매일/격일).
- **실패율 임계** — 5% 초과 시 베타 중단 vs 즉시 핫픽스 후 연장.

## 6. 변경 영향도 점검

- `client_python/` 내부 + `docs/operations/` 신규 1건. 코드 행위 변화 0건 (가드/분기 추가만).
- 빌드 의존성 신규 1건 (`pyinstaller`) — `build.bat` 실행 시 자동 설치, requirements.txt 에는 포함 안 함 (점주 PC 에는 불필요).

## 7. 알려진 한계 (Phase 5 백로그)

- **SmartScreen 경고** — 코드 서명 부재로 첫 실행 시 항상 발생. 가이드 §4-2 안내 + Phase 6 의 EV 서명 도입 시 해소.
- **아이콘 디자인** — 임시 단색 원. PyInstaller spec 의 `icon=` 파라미터는 현재 주석 처리, Phase 5 본 빌드 시 .ico 추가.
- **자동 업데이트 부재** — 점주에게 새 .exe 를 USB/링크로 재전달해야 함. Phase 5 의 Velopack 도입으로 해소.
- **`build_entry.py` 자동 생성** — spec 실행 시 매번 spec 가 entry stub 을 만드는 구조. 빌드 후 정리는 `build.bat` 의 책임 (현재는 다음 빌드 시 덮어쓰기 + .gitignore 처리). 깔끔함은 Phase 5 정비.
