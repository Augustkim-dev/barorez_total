## 4. 핵심 결정

### 4.1 작업 단위 분할 = 5개 묶음 (D007~D011)
- 사용자 합의: 산출물별 11건은 commit 너무 잦음 → 골격/인증/디스패처/콜백/배포 5개 단위로 통합
- D007 = D1+D5+D2+D11 (골격 + SQLite + Webhook + 환경변수)

### 4.2 Webhook body 에 jobs 상세 동봉
- 초기 형식 (Phase 1 D006): `{job_ids:[12345], shop_id:42}` — Server C 가 PHP 별도 GET 필요
- 변경 후: `{shop_id:42, jobs:[{job_id, printer_type, payload}]}` — Server C 자족
- 사유: D008/D009 단위에서 PHP API 추가하지 않아도 됨, webhook 1회 호출로 적재 완료
- PHP 측 send_print_webhook() 가 print_job_t 에서 SELECT 추가 (job_idx IN (...))

### 4.3 SQLite 멱등성 = `INSERT … ON CONFLICT(job_id) DO NOTHING`
- PHP 가 같은 job_id 로 webhook 재발송해도 SQLite 에 중복 INSERT 안 됨
- 응답 본문에 `{inserted, duplicate}` 카운트 명시 → 디버깅 용이

### 4.4 잘못 추정한 점 (PRD 와 차이)
- PRD §10.1 의 SQLite 스키마는 `created_at DATETIME` 이지만 SQLite 는 DATETIME 타입 미존재 → TEXT + ISO8601 (`CURRENT_TIMESTAMP`)
- PRD 의 `printer_type ENUM('kitchen','counter','bar')` → SQLite CHECK 제약으로 동등 효과

## 5. 검증

`npm run dev` 로 dev 서버 기동 (`tsx watch`, port 3000) 후 다음 케이스 모두 통과:

| 케이스 | 입력 | 기대 | 결과 |
|---|---|---|---|
| GET / | — | 200 "Server C alive" | ✅ |
| GET /health | — | 200, queue 통계 JSON | ✅ |
| POST /webhook/print (헤더 없음) | body only | 401 missing signature | ✅ |
| POST /webhook/print (잘못된 sig) | X-Signature: deadbeef | 401 invalid signature | ✅ |
| POST /webhook/print (정상 sig, ASCII) | shop_id=48, jobs=1 | 200, inserted:1 | ✅ |
| POST /webhook/print (정상 sig, 멱등) | 동일 body 재호출 | 200, inserted:0, duplicate:1 | ✅ |
| POST /webhook/print (정상 sig, 한글) | 한글 menu/memo | 200, inserted:2, queue:3 | ✅ |

검증 데이터는 `server_c/data/server_c.db` 에 남음 (commit 시 .gitignore).

### 검증 시 발견·해결한 시행착오
- **Windows git-bash 환경변수의 한글 인코딩 깨짐**: cURL `--data-raw "$BODY"` 로 한글 페이로드 검증 시 401. 원인: BODY 환경변수에 들어간 한글이 cURL 송신 시점과 node sign 시점에 다른 인코딩으로 처리됨.
  - 해결: `node --input-type=module -e ...` 로 sign + fetch 를 한 프로세스에서 처리 → 정상 200
  - 운영 영향 없음 (PHP 측은 동일 프로세스 내 json_encode + curl 이라 인코딩 불일치 발생 안 함)
