## 2. 핵심 결정 사항

| 항목 | 결정 |
|---|---|
| 권한 모델 (D5) | 매장 소유자(`shop_t.mb_idx = $_SESSION['mng']['mt_idx']`) **OR** 슈퍼 관리자(`mt_level >= 8`) |
| HTTP 메서드 (D5) | POST (D4와 동일 컨벤션) |
| 인증 방식 (D5) | 세션 쿠키 (HMAC 아님 — 사람이 직접 호출하는 API) |
| Webhook 발송 패턴 (D3) | fire-and-forget, 500ms 타임아웃, throw 금지 (D2 hook에서 주문 흐름 차단 방지) |
| 라우팅 규칙 폴백 | 규칙 없는 메뉴는 `counter`로 폴백 (사일런트 누락 방지) |
| `also_print_at_counter` 정책 | 전체 items를 카운터로 보냄 (PRD §5.1.2 "카운터 영수증은 모든 주문") |
| 재출력 시 페이로드 | 원본 `payload` JSON 그대로 복사 (재빌드하지 않음 — 원본 의도 보존) |

## 3. 검증 결과

운영 서버에서 사용자가 직접 `test_retry.sh` 실행:

```
[검증1] 미로그인           → 401                                      ✅
[검증2] GET 메서드         → 405                                      ✅
[검증3] 정상 호출 (세션)   → {"ok":true,"new_job_idx":6}              ✅
[검증5] 존재하지 않는 id   → {"ok":false,"error":"not_found"}        ✅
```

API 동작 정상. 인증 가드, 메서드 검증, row 복제, 404 처리 모두 의도대로.

권장 추가 확인:
- 검증 4 (다른 매장 job_idx → 403): 본 검증에서는 미실행. 권한 모델 자체는 코드 리뷰로 확인되었으나, 실제 운영 중 다른 매장 매니저의 오접근 차단을 보장하려면 향후 한 번 시행 권장
- `create_print_jobs_for_order()` dry-run: 본 단위에서 직접 호출자 없음. **D2 단위에서 자연스럽게 검증됨**
- DB 확인: `SELECT * FROM print_job_t WHERE job_idx IN (5, 6);` — 원본 5와 신규 6의 payload·shop_idx·order_idx·printer_type 일치 확인
- error_log: Server C 미존재로 `[print] webhook send failed: ...` 출력 — 정상 (fire-and-forget 의도대로)

## 4. 검증 과정에서의 학습

### 4.1 세션 쿠키 진단

검증 3·5 첫 시도에서 `unauthenticated`가 떴는데, 원인은 `test_retry.sh` 안 `COOKIE='barorez=<...>'` placeholder 미치환. 사용자가 브라우저 개발자 도구에서 실제 쿠키 값을 추출해 치환 후 정상 통과.

**향후 시사점**: 세션 인증이 필요한 API 검증 시 placeholder 치환 확인 단계를 검증 스크립트 상단에 명시 (예: `[ -z "${COOKIE##*<*}" ] && echo "ERROR: COOKIE placeholder not replaced" && exit 1`).

### 4.2 `lib.inc.php`가 세션을 자동으로 셋업

`api/print_jobs_retry.php`의 첫 줄 `include lib.inc.php`만으로 `$_SESSION['mng']`가 즉시 사용 가능. 별도 `session_start()` 호출 불필요. D2에서도 동일 패턴.

## 5. D2(Phase 1 최종)로 미루는 의사결정

`create_print_jobs_for_order()`와 `send_print_webhook()`은 정의되었으나 자동 호출자가 없음. D2에서 [app/actions/order/order.php](../../web/public_html/app/actions/order/order.php)의 3개 함수에 hook 삽입:

| 함수 | INSERT 라인 | Hook 라인 (검증 성공 직후) |
|---|---|---|
| `createOrderPostpaid` | L224 | L243 |
| `createOrderCommon` | L648 | L666 |
| `createOrderReservationPostpaid` | L685 | L704 |

Hook 패턴 (3곳 동일):
```php
require_once $_SERVER['DOCUMENT_ROOT']."/cfg/print.inc.php";
$_print_jobs = create_print_jobs_for_order($order_idx);
if (!empty($_print_jobs)) {
    send_print_webhook($_print_jobs, $shop_idx);
}
```

공통 wrapper 함수로 묶을지, 직접 호출할지는 D2 plan에서 결정.
