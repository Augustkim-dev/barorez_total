## 3. 핵심 결정

### 3.1 PHP 콜백 URL 형식
- D004 의 `api/print_jobs_status.php` 는 `?id=<job_id>` 쿼리스트링으로 받음 (path param 아님)
- callback.ts 도 동일하게 `POST {PHP_API_BASE}/api/print_jobs_status.php?id={jobId}` 호출

### 3.2 콜백 재시도 백오프 vs Job 재시도 백오프
- **Job (PRD §8.2)**: 1s → 3s → 10s, 3회 후 failed — Server C 가 client 에게 재dispatch 하는 백오프
- **PHP 콜백 (본 단위 신규)**: 1s → 5s → 30s, 총 4시도 후 포기 — Server C → PHP 가 일시 다운 시 안정성
- 두 시퀀스는 완전히 독립 — 같은 변수명 X (BACKOFF_MS vs RETRY_BACKOFFS_MS)

### 3.3 PHP 콜백 최종 실패 처리
- 4회 시도 모두 실패하면 `recordError('php_callback_failed')` + ERROR 레벨 로그
- DB(SQLite) 는 이미 printed/failed 로 갱신된 상태 → PHP DB 와 일시 불일치 가능
- Phase 6 운영 모니터링 단계에서 `php_callback_failed` 알림 추가 권장 (Slack/Email)

### 3.4 production 로그 = stdout + 파일 동시 기록
- pino `multistream` 으로 두 곳 동시 출력
- stdout → PM2 가 자동 캡처 (운영 콘솔 디버깅)
- 파일 → pino-roll 자체 회전, OS 단 logrotate 의존도 0
- 보관 기간 30일 (PRD §9.1)

### 3.5 로그 이벤트 이름 일관성 (PRD §9.1)
실제 코드 베이스에서 사용되는 event 종류:
- webhook 흐름: `webhook_received`
- 클라이언트 흐름: `client_connected` / `client_authenticated` / `client_disconnected`
- 디스패치 흐름: `job_dispatched` / `sync_dispatched`
- ACK 흐름: `ack_received` / `ack_redundant` / `ack_unknown_job`
- 재시도 흐름: `retry_scheduled` / `job_failed`
- PHP 콜백 흐름: `php_callback_printed` / `php_callback_failed_call` / `php_callback_retry` / `php_callback_failed`
