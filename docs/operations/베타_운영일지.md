**관찰 노트**:

- **운영 첫날 핫픽스 4건 다발 적용**. 베타 매장이 D013 시점 빌드를 그대로 쓰지 않고 D016 까지 누적된 다듬기를 같은 날 받게 됨:
  - 영수증 4컬럼 표(메뉴명·단가·수량·금액) + 단위 `원/개` + 메뉴 사이 줄간격 (`09ceadbc`).
  - 다른 PC 배포 시 `wss://` 핸드셰이크 `CERTIFICATE_VERIFY_FAILED` — `certifi` CA 번들 동봉으로 해소 (`a460ef89`, `2322a75f`).
  - `build.bat` 의 `Size:` 빈칸 출력 (`fb6ca591`) — 사소한 표시 이슈, 빌드 자체에 영향 없음.
  - `orders_t.ot_table` 가 `shop_table_t.idx` 라 영수증 테이블 번호가 손님 좌석 번호와 불일치하던 버그 + 옵션이 dict repr 로 인쇄되던 버그 (`d018bcb6`).
- 핫픽스 직전 데이터의 영수증은 모두 위 형태로 인쇄됨. **안정화 시점은 PHP 운영 동기화 + `.exe` 재배포 완료 시점 (사용자 보고: "처리완료")**. 그 이후 발생한 주문부터 새 형식.
- WS 연결 자체는 D013 운영 검증 시점부터 안정적. `auth_ok client_id=2 shop_id=48` 응답 일관, 재접속 동기화로 큐 누락 0건.

**조치 / 결정 사항**:

- 18:00 영업 후 점검 시 정량 지표 일괄 회수 (운영 일지 §4.1 SQL 그대로).
- 1일차는 핫픽스 다발일이라 실패율·지연 지표가 평균을 왜곡할 수 있음. **안정화 평가는 2일차(2026-05-16)부터** 기준으로 1주 종료 정리에 반영.
- 옵션 가격 0 인 항목은 이름만 표시 — 점주 피드백 수집해서 "필수 옵션 선택 / 변경 옵션" 구분이 필요한지 차주 검토.
- `app_version=0.1.0-d016` 인 client 가 운영 매장에서 1대 동작 중. 다음 빌드 시 `0.1.0-d017` 로 bump 할지 논의.
